# “人员与能力”统一集成实施报告

## 本次已完成

- 复用航线运行中心已有的“人员与能力”一级页签，没有建立第二个同名入口。
- 页签内部保留“主数据管理”，并新增按需加载的“能力配置”区域。人员列表、组织班组、人员详情、授权项目、导入中心、数据质量和变更历史仍由原页面负责。
- 能力配置包含综合看板、调配工作区、派驻、培训状态、其他状态、历史、方案、报表，以及重点项目和门限配置。
- 行政归属、当前工作班组和当前状态分开保存。跨班组操作只改变当前工作班组；派驻、培训和其他状态不作为可拖拽班组。
- 只统计有效授权；普通项目按“人员ID＋项目代码”去重，三方项目按“人员ID＋授权单位＋项目代码”去重。121/145数量不参与班组比较。
- 看板数据、状态、调配、方案和配置通过服务接口访问；写操作带版本号、请求标识、权限及人员范围校验。
- 调配、状态变化和补偿操作采用追加式历史；撤销不会删除原记录。
- 同一服务进程内即时推送变化，共享同一数据库的其他服务进程通过短周期版本检测同步。

## 数据责任

- 中心人员、组织、执照、授权、培训明细和授权项目目录是唯一主数据来源。
- 能力模块只新增当前状态、支援、派驻、培训状态、其他状态、历史、方案和配置等业务数据。
- “培训明细”与“培训状态”含义不同。结束培训状态不会生成培训证书或授权。
- 原导入中心是唯一正式导入口；能力配置只跳转，不复制导入功能。

## 旧页面数据排除

- 正式页面和接口不接受旧网页JSON快照，也不读取旧浏览器存储。
- 原134人、旧授权分布、旧状态、旧方案和旧门限只存在于隔离自动化测试，不进入中心数据库。
- 检测到来源未核实的能力业务表时正式能力功能失败关闭，必须先归档，再使用显式初始化工具清理能力业务表。
- 初始化工具不删除或覆盖中心人员、组织、执照、授权、培训、项目目录及维修业务数据。
- 人员唯一对应只使用中心不可变人员ID；工号仅用于中心导入匹配，姓名不参与匹配或合并。

## 验证结果

- 原134人和既有授权分布仅作为隔离算法回归样本，不作为正式数据或上线人数标准。
- 正式数据验收以航线运行中心当前人员主数据库为准。
- 验证了同组排序、跨组调配、悬停调配、撤销补偿、实际/行政双口径、状态互斥、未来状态、方案原子应用、权限范围、并发版本、幂等请求、两客户端更新和重启持久化。
- 原人员列表与导入中心回归通过；1440×1024和1060×710两种尺寸完成视觉检查，浏览器控制台无错误或警告。

## 客观边界与上线前必做

本次完成的是工作区内的集成实现和隔离数据验收，不代表生产上线。以下项目在真实环境确认前不能省略：

1. 用中心最新数据库做只读对账；不得为了匹配旧测试样本而修改真实人数。
2. 确认生产数据库迁移脚本、备份、执行窗口和数据库账号权限。
3. 核对真实登录、人员范围和各角色权限，禁止保留本地管理员切换作为授权手段。
4. 在多实例部署环境验证SSE、会话共享和反向代理的长连接配置。
5. 先只读开放，再开放调配和状态写入；生产写入应单独授权。
6. 本轮不改变维修派工资格判断和历史工时归属。若未来联动，必须单独定义规则并验收。

## 回退步骤

1. 关闭“能力配置”区域的路由或功能开关，原“主数据管理”继续使用。
2. 停止能力状态调度和事件推送，阻止新增写入。
3. 导出能力业务表和事件历史作为审计备份。
4. 回退应用版本；不要删除中心人员、执照、授权、培训和项目目录主数据。
5. 新增能力业务表应保留到问题复核结束。只有在确认无需恢复且完成备份后，才执行独立清理脚本。

这样回退不会影响原人员列表、导入中心和其他航线运行中心模块。
