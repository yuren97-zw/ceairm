# 统一人员身份与分模块范围：实施记录

更新：2026-09-01。状态：代码及独立库接口回归已完成，8788测试服务已在离线备份和只读预检通过后切换到当前工作树代码；**尚未完成真实组织数据和生产环境验收**。不应把本文件理解为生产上线确认。

## 已实现

- 人员业务引用统一为 personId / person_id；工号是8位唯一业务码且接口拒绝修改；账户ID仅用于登录、操作人和回执。
- 6类维修人员关联表和报工草稿迁移到人员ID；信息接收关系同时保存人员ID和实际接收账户ID。保留迁移追溯，不运行账户ID/人员ID猜测回退。
- 信息本人操作按发布账户或创建账户判断，不再按姓名；账户禁止换绑，数据库保护同步限制换绑。
- 六模块分别配置范围：人员、账户、信息、维修、工时、考勤。同模块取并集，跨模块不继承；未配置的新账户模块为本人；每次访问计算生效和到期时间。
- 人员列表SQL范围过滤、分页、搜索、筛选项、统计、详情、修改和变更日志均使用统一访问服务；范围外目标404、缺少功能权限403。
- 个人背景字段按敏感信息权限裁剪；隐藏的表单字段不提交；资质数量和资质变更日志按资质查看权限过滤。
- 普通资料、正式组织、敏感资料分别校验权限。组织调动检查调动前后范围；未分配新人员仅人员全部范围操作者可创建。
- 正式组织目录支持部门、可选车间、班组。固定代码、类型、父级；改名有原因和审计；引用保护包含人员、子组织、范围和组织历史。
- 用途白名单人员目录：开户、信息接收、维修。信息候选必须有可用账户。通用设置不再返回全员目录。
- 信息接收必须显式选择；“选择可发送范围内全部人员”由服务端按提交时范围解析。
- 人员四类导入在暂存、确认两阶段检查当前权限、范围、组织和删除状态。跨范围或敏感批次不直接暴露全批详情；取消限制为创建者或全部范围导入管理员。
- 账户查询、开户、停用、重置、角色与范围设置检查账户模块目标范围。批量开户拒绝覆盖现有账户、未知范围、旧格式和错误组织。
- 维修候选、目标成果和批量确认加入范围检查；跨范围批量操作整笔拒绝。安全删除阻断使用人员ID；历史资料和接收人姓名快照不随主档修改而重写。
- 身份与组织范围迁移同事务完成；任何歧义、孤立关联、唯一键冲突、组织归属不明都阻断。启动前预检失败时不进入初始化迁移。

主要文件：personnel-access.mjs、personnel-identity.mjs、personnel-deletion.mjs、server.mjs、public/app.js。

## 对接格式

人员目录：GET /api/personnel/directory?purpose=accounts|info|maintenance&q=关键词&page=1&pageSize=50

响应 items 每项包含 personId、employeeNo、name、department、homeTeam、position，以及该用途需要的 accountId/accountStatus。调用方不能传入权限名获取任意范围或完整个人背景。

账户 scopes 示例：

```json
[
  {"module":"personnel","scopeType":"home_team","scopeId":"","validFrom":"","validTo":""},
  {"module":"info","scopeType":"all","scopeId":"","validFrom":"","validTo":""},
  {"module":"maintenance","scopeType":"managed_teams","scopeId":"组织ID","validFrom":"2026-09-01","validTo":"2026-09-30"}
]
```

日期按北京时间包含首尾整日，保存为UTC带时区时间。支持 self、home_team、department、managed_teams、workshop、all。指定组织只接受对应类型的目录对象。

批量开户列：

- 员工工号、登录账号、初始密码、账户状态、角色。
- 人员与能力范围、登录账户管理范围、信息传达范围、维修管控范围、工时统计范围、考勤管理范围。
- 各范围可附加“开始日期”“结束日期”列，例如“维修管控范围开始日期”。格式 YYYY-MM-DD。
- 指定范围写“指定班组:组织代码”或“指定车间:组织代码”；同模块多项用 | 分隔。空白默认本人。旧“数据范围”列不再接收。

工时和考勤仅预留范围模型，未建设这两个独立业务模块。
