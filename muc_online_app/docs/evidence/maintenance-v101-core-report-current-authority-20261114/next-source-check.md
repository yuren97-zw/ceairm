# 后续原报工身份与授权竞争

本轮原锁内当前操作者校验涵盖例行、放行及整体确认保存/完成，自动路径仍是内部inTransaction调用。下一步实际双服务锁等待后单独改变参与关系、原放行人/批次签署来源及当前人员绑定，核对合法已提报或已确认事实不被重写，不能把三个role/status注入场景当作全部身份矩阵。

原replaceMaintenanceAssignmentsFromEntries仍将正式提交实际人员写入原关联，applyMaintenanceReleaseSelection仍在正式例行提报时调整归属；本轮只是当前资格补强，不等于完成原派工与实际报工结果的独立承载。进一步改动须核对正式批次、分配器、结果唯一来源、自动完成门槛、任务树复核和已确认更正，不得直接去掉关联更新而失去合法实际工时/架次来源。
