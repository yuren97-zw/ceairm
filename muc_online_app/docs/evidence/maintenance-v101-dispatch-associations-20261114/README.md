# 正式派工关联保留及独立删除（2026-11-14）

## 实施前核对

原方案4.2/P0-07/08要求关联去重、顺序无关、取消勾选不隐式删除，删除必须独立展示影响并明确确认。实际源码setMaintenanceAssignments对每个可编辑关联先删除反馈、工时、架次及关联，再重建传入集合。真实原路由回归复现重复提交也改变原关联ID/时间，失败日志保留。原派工导入仅允许尚无派工/报工的机会，不依赖替换现有集合。

## 实际变更

原正式派工改为只插入缺失关联，既有ID/人员/工种/时间/反馈/结果保留；省略旧选择不会删除，重复及顺序变化跳过。已有放行不能通过选择另一人员隐式替换，须先独立删除旧关联。锁定类别不能新增成员，原已锁定关联保留。权限、当前有效人员、机会范围及当前版本在原事务锁内复查；新人员再核对当前范围。

独立预览绑定单个关联、机会版本和当前共享草稿全文/版本摘要。明确原因及确认摘要齐备才能删除。报工锁定、非已派工状态、已有反馈或任何工时/架次结果均拒绝；不抹除正式事实。删除保留草稿并明确提示后续报工须核对其人员，不自动清空/改写草稿；草稿或机会变化使旧预览失效。原日志在同一事务保存删除对象、派工来源、原因和保留草稿版本；审计失败整笔回滚。

原派工页面增加既有关联独立预览入口和提示，显示已选人数/工种/待新增数，删除取消或失败保持原窗口。仅成功删除后刷新并明确放弃未保存选择。缓存v43。桌面布局检查发现误用20px复选框列导致文字竖排，已以本窗口局部样式修正；桌面和390宽最终截图已查看。
