# 非例行下一步实施边界

实际原路由复现：旧mode=save首次保存临时工作会建立正式subtask及派工；再次保存同一已存在未提报工作，改选主做人会替换正式关联。NONROUTINE_DRAFT_MUST_NOT_REPLACE_FORMAL_DISPATCH断言失败，日志及探针片段已保留。仅在复制当前原测试源的临时文件运行这一用例，运行后删除该临时副本，没有向日常测试集合加入已知失败用例，也没有更改产品。探针只创建隔离合成数据。

normalizeMaintenanceNonroutineDraft当前只保存clientId/文字/人员，不保留formal subtask id；原页面将所有draft.items转为temporary上下文。saveMaintenanceNonroutine又把临时来源草稿和formal项分开，后者继续applyMaintenanceNonroutineChanges。因此不能简单把旧保存改调现有草稿接口，否则同一正式单项可能变成第二临时项、丢失身份或重复创建。

下一步须增加绑定当前机会及真实subtask身份的可编辑草稿投影；保存现有项的人员选择不改派工，读取要以身份覆盖原报工上下文、保留临时项稳定clientId及标准来源，旧无formal身份草稿仍按旧真实来源解释。共享版本冲突、来源删除、标准锁定、正式提交批次及实际人员结果需一起核验，不能自动重编号或回填旧已提报记录。正式提报仍改变原实际人员/结果服务，完整派工与报工身份独立尚待实现。
