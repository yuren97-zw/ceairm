# 非例行正式派工与实际报工来源分离

按方案§4.2/4.3重新核对后，真实接口复现非例行正式提报替换派工。现正式提交先形成批次/条目，再冻结认定/评议参与事实，最后调用原唯一核算；整体确认也先修订批次再重算。只推进原派工任务状态，保留身份、来源、派工时间，不创建实际人员对应的假派工。移除已无调用的原报工替换派工桥接函数。

统一内部实际人员读取由真实batch/entry及工作项归属契约核验，保留旧认定中冻结的来源引用/原结果兼容身份；无批次及未知版本0历史沿原适配，不补造历史。评议基线/变化核验、终审预览/入账、核算角色子记录、授权更正、任务树复核统一读取实际参与。领域服务通过内部回调接入，不接受客户端指定读取器。复核实际人员变更进入报工新版本，原提报与原评议不改写。

确认前先推进正式批次状态再派生工作状态，避免确认后工作项回到待复核。复核首次补录先形成真实实际来源再生成结果，不新增派工。审计明细分别保留派工人数和实际参与人数，保留原施工角色/认定核算角色；列表与导出分段预取来源，人员/班组/姓名搜索按实际来源或有效结果，旧无来源才回退正式派工；作用域继续逐人过滤。

新增原API链：原派工root、实际人员peer、正常2小时提报→整体确认→授权改为另一人→确认，派工身份始终不变；未收录实际人员经原共享草稿→原提报产生唯一评议→整体确认/任务树确认，原事实token稳定、仍待受理且0正式小时；复核首次补录另一实际人员，真实2小时确认且无假派工。领域测试证明派工变化不改变实际基线、实际变更仍被识别，以及已提报/待复核/已确认三阶段的独立来源核算角色展开与2.1小时守恒。

旧回归中以报工隐式生成派工为前提的预览、拖机、角色来源断言改为查真实报工条目/冻结引用，并保留原金额、角色、幂等、回滚等断言。实际发现并修复的产品依赖为审计缺失来源展示与确认状态更新顺序；首次补录假派工另有修前失败证据。新未收录测试在已有相同ATA候选时须明确人工确认不同工作，未绕过标准匹配门槛。
