# 结果来源继续分离的真实调用顺序

当前submitMaintenanceRoutine先写批次，再替换关联、生成例行结果；整体确认先替换例行批次条目，人员变化时再生成，已核对当前切换的顺序成立。旧work-report公开GET/PUT固定410，旧内部整合生成函数没有当前公开调用。

任务树复核另走reconcileMaintenanceReviewAssignments及rebuildMaintenanceReviewResults，仍从原关联重建实际结果，并非本次新批次读取。例行复核还保留原批次，不应为了接新来源擅自覆写已锁定原始提报快照。后续须分清原提交事实与授权复核后的有效实际参与事实，保留原批次及复核版本/依据，不能让以后重读原批次把合法复核改动回退。

放行架次仍读原放行关联；非例行部分路径在统一批次更新前生成结果，来源不能照搬例行顺序。新认定/实际身份更正还带冻结角色分配及不可变回执，不能把报告条目ID替代已批准来源ID而重复入账。先逐个建立权威实际来源及读优先级，再让正式派工独立保留；最终仍需核对执行可见性、原派工资格、五态、整体确认和已确认锁定，不以本轮单一读取切换当作完整分离。
