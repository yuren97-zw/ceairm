# 考勤隔离暂存迁移工具（非生产切换工具）

本工具仅将8792的一致性SQLite备份中的28张考勤/假期表，合入“云库恢复后、考勤表为空”的本机PostgreSQL16暂存库。保留云端原有账号、认证、人员ID、维修、信息和权限数据，不导入源账号凭据、会话或源人员主档。

## 前提与边界

- 源必须是停止写入后取得的一致性备份，不直接指向运行中8792的数据库；存在非空WAL/journal时拒绝。先保存源文件SHA-256。
- 目标必须为127.0.0.1/localhost/::1的明确临时端口（禁止5432、8787、8788、8792），数据库名以`_attendance_stage`结尾，不接受连接查询参数。先恢复云端最新一致性备份，再执行项目迁移；**不要启动应用或同步任务**。
- 报告目录必须已存在且权限700，报告文件不得已存在。文件以600创建；不记录认证材料和人员明细。
- 默认预检，只读源和目标。正式执行需预检摘要和显式环境确认；全程事务、互斥锁和表锁，目标变化或锁超时即停止。
- **工具不能连接生产库，不能把本机暂存验收等同生产迁移批准。** 不提供强制覆盖、按工号重建人员、部分导入或直接增量混库选项。

## 执行

通过本机受控环境设置`DATABASE_URL`和`ATTENDANCE_SOURCE_SQLITE`；不要把数据库密码写入命令行参数、报告或仓库。

```sh
npm run migrate:attendance-stage -- --plan --report=/private/acceptance/plan.json
```

检查报告中的人员覆盖、未匹配未引用人员、总行数、逐表摘要和`planHash`。只有准备好了空考勤暂存目标且计划经过确认，才执行：

```sh
ATTENDANCE_STAGE_CONFIRM=ISOLATED_ATTENDANCE_STAGE npm run migrate:attendance-stage -- --apply --expected-plan=已确认的64位planHash --report=/private/acceptance/applied.json
```

上例中的`planHash`必须替换为实际64位十六进制值。参数内不传人员数据或凭据。若环境或计划改变，重新预检，不绕过保护。

## 映射与校验

- 人员只按去除首尾空格后的唯一工号映射到既有云端personId；操作账号按唯一登录用户名映射。重复、空身份或任何实际未匹配引用均拒绝。没有引用的未匹配人员只报告，不新增/删除。
- 区分personId、accountId、工号与钉钉userId。按字段语义转换列、范围数组及JSON；不全文替换。未知表、列、JSON身份位置须人工审查后更新契约。
- 审批到期任务按既有算法重算标识；已发生的历史run_id保持，运行、批次、人员与JSON成员必须一致。审批缓存允许明确关联普通同步运行或审批事由补齐任务。
- 每表导入后对比转换结果摘要。任务、审批、消费、分类、原始输入、source_hash、调用计数和历史记录保留；不重算考勤或工时，不调用钉钉。
- 使用事务性序列重启和`data_import_checkpoints`中的`attendance-stage-v1`检查点。精确来源/目标相同才允许无写入重跑；任何后续修改均拒绝，不用旧来源覆盖新目标。
- 应用一旦启动或产生新数据，通常不再满足精确重跑条件。不要删除检查点；如需追平更新源，重新用最新云库副本建立新的空考勤暂存库再演练。

## 最终上线另行处理

最终冻结、8792停止真实同步、最新一致性副本及增量对账、唯一同步实例、生产迁移执行和回退都须另获授权。租约、待执行队列、同步游标和历史连接快照被完整保留，不代表允许立即启动工作队列。不能同时启用8792与云端同步，不全月重放。

当前工具不是通用“差异合并”算法，也不覆盖COS对象、附件目录或服务器配置的备份与恢复；这些必须单独验收。生产配置只能受控加密保存，禁止写入Git或普通日志。
