# 本地、GitHub与腾讯云版本对应

## 基线与发布

本次收录的是此前独立部署版本 `v14-home-shell-20261113` 的考勤、假期、抵消审批、统一待办及首页交互代码，包含032增量迁移和对应自动化测试。旧独立包用于回退和证据留存，不作为今后的源码来源。

正常流程：本地开发分支提交 → 推送GitHub → PR的verify通过 → 合并main → main对应提交的CI通过 → 人工批准运行Release production → 部署该提交的不可变Release。云端版本名为 `production-<完整提交SHA>`，必须能追溯到GitHub上的同一提交及归档校验值。不要仅更改云端版本标签来宣称对齐。

发布工作流保留手动触发、明确目标SHA、成功CI和production环境保护。不得用跳过检查、强推或关闭保护解决发布失败。main若在构建期间前进，重新核对目标版本，不将旧构建标成新提交。

云端版本确认后才恢复release poller；恢复前确认GitHub最新Release就是批准的版本，避免旧包覆盖现站。部署前备份数据库、代码与必要配置，增量迁移后核验健康、关键数据和同步状态。回退代码保留新增结构及业务流水，不拿旧数据库覆盖其他模块的新业务数据。

## 数据与配置

GitHub只保存源码、迁移、测试和可公开说明，不保存.env、凭证、数据库、上传附件或真实人员考勤快照。本地与云端数据库独立；复现问题可使用授权的隔离备份副本，不能反向覆盖云端数据。

现站的角色授权、实际当班责任、首期固定次数、额度/申请/审批流水及钉钉配置属于服务器持久化数据或配置，不随Git代码重置。首次部署或恢复需单独验证，不能从示例人员、行政班组或测试参数推断实际政策。

本地仍使用既有8792入口和独立配置；版本对齐不意味着自动开启第二套真实事件消费者或同步任务。启动前确认当前本地阶段和开关，避免与云端重复消费。

已包含秒级累计、月度兑换和首期固定2次、本人申请、实际当班责任审批、统一待办、独立假期年度查询及过滤、共享类别配色、首页抽屉与个人日期详情联动。原始钉钉事实和内部抵消结果分别保留。

永久忽略“新冠关爱假”“公休假（2025年度延长）”；历史源记录仅保留追溯，不参与对应类别或假期余额展示。通用接口可能夹带原始信息，不能承诺钉钉端完全不返回这些内容。

已有自动化、合成浏览器及部分真实设备/原站流程证据，不代表全部业务、PWA或长期运行验收完成。未确认的跨月、结转及差异调整政策继续保持未开放，不因版本合并放宽。

每次发布记录：源提交、PR与CI链接、Release版本、包SHA256、服务器备份位置、迁移版本、健康结果、数据一致性及未覆盖项。设备截图和含业务数据的验收材料放在受保护的本地/服务器目录，不进入源码仓库。
