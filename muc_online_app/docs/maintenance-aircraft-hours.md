# 机型组标准工时

## 使用

在维修管控的工时规则页，展开“机型组 × 维修机会标准工时”，新增机型组。
每列填写组名、多个机型代码和各维修机会的总工时。代码支持空格、逗号、顿号、分号及换行；统一转大写并去重。
例如 `32N 320 32N 325` 保存为 `32N 320 325`，同列三种机型共用各行工时。

机型精确匹配，不自动认为 `320` 等于 `A320`。同一代码不能属于两个组，停用组也保留代码占用，避免重复归属。
空工时表示未配置。未填写或未匹配的航班可以录入、导入、派工及保存草稿，但不能提交涉及人员工时的例行报工。
纯放行架次、非例行和拖机不依赖此矩阵。

初次不自动创建组或套用旧工时，管理员需明确配置新矩阵。旧标准工时不再展示或通过工时规则接口维护，仅保留数据供历史兼容。
保存前显示未报工航班影响预览（明细遵循现有航班可见范围），填写原因后整笔提交。
并发修改规则或影响航班变化会拒绝过期提交，要求重新刷新或预览。

## 历史与权限

首次提交例行工时保存机型、组、维修机会、总标准工时、比例、版本及时间快照；以后修改矩阵不重算已有报工。
复核人员调整继续使用原快照；原有归档改动原因及审计规则保持不变。
历史报工启动时幂等补建旧规则快照，不改已有工时结果，不把旧默认工时分配给新机型组。

查看与维护沿用 `maintenance.rules.view` / `maintenance.rules.manage`，不新增权限。
机型组存于 settings 的 `maintenance_aircraft_hours_v1`；航班新增只读快照字段 `routine_hours_snapshot`。
PostgreSQL 使用迁移 `017_aircraft_hours_snapshot.sql`，SQLite 启动时幂等补列。
发布包已包含新增计算模块。
