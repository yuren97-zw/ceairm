# 统一导入与例行派工导入

派工页只有一个导入入口，按现有权限选择航班计划、附加工作、例行派工。上传、服务端检查、预览、确认和结果均在弹窗中完成；模板可下载为 Excel，结果可下载为 CSV。

## 派工字段与规则

日期、航班号、维修机会、放行人员、维修人员为模板列。放行人员必须恰好一名。维修人员用英文/中文逗号、分号或换行分隔。放行工号、维修工号可选；提供时与对应姓名按顺序一一对应。姓名在可派工范围内精确匹配，同名需工号。

短停：日期＋进港/出港两个号码＋短停。航前：日期＋出港（允许 /出港）＋航前。航后：日期＋进港（允许 /进港）＋航后。匹配无结果或多结果均拒绝；不能自动创建或猜测。唯一匹配后必须为未派工且无残留派工或报工。

| 类型 | 放行人员角色 | 每位维修人员角色 |
|---|---|---|
| 短停 | 放行、例行检查 | 接机、送机 |
| 航前 | 放行、例行检查 | 勤务、送机 |
| 航后 | 放行、例行机外、例行发动机、例行L/G | 接机、勤务、例行机内、例行电子 |

两列不合并分工；同一人同时填写两列时取得两列的角色并去重。仅例行派工，不处理非例行。

## 接口

- POST /api/maintenance/dispatch-import/preview：只读检查，返回逐行结果、人员角色、匹配 ID 和更新时间。
- POST /api/maintenance/dispatch-import/commit：带原始 rows、matchedFlightId、expectedUpdatedAt 和 requestId。每维修机会独立事务，批次部分成功；失败整条回滚。成功状态必须为已派工。重复请求按账户与请求编号保存的提交记录幂等，重试仍复核当前人员范围。
- 航班和附加导入原接口增加 validateOnly，检查不写入；提交保留原业务规则。

文件内同维修机会重复行全部拒绝。预览后更新的维修机会拒绝。不扩大权限、范围或报工确认流程。
