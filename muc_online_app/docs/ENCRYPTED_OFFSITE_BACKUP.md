# 加密异地备份（独立程序已安装，生产定时任务已启用）

## 目标与权限

- 专用桶：ceairm-backups-1449362740，ap-beijing；私有读写、SSE-COS已由控制台核实。
- 仅 encrypted/v1/ 前缀，拟授权既有服务身份 PutObject / HeadObject / GetObject；无删除、列全桶或管理权限。授权必须另经确认，不能因附件桶权限而自动认为已获授权。
- 不将任何恢复私钥、明文数据库、应用配置或COS凭据写入仓库、日志或对象存储。服务器仅有RSA公钥。
- 上传前AES-256-GCM流式加密，每个文件使用独立随机密钥，以RSA-OAEP-SHA256封装；元数据绑定快照、用途与公钥指纹。SSE-COS是额外保护，不替代客户端加密。

## 数据与完成口径

备份包含 PostgreSQL custom-format 数据库及应用 shared/.env。不是整个服务器镜像，不包含COS附件原件、本机恢复私钥或完整操作系统配置。附件桶本身的容灾需另行安排。

pg_dump 凭据仅经子进程环境传递，不在命令参数中出现。数据库从标准输出直接进入加密流，服务器不生成明文中间dump；加密工作文件权限600、目录700。单文件上限2GiB、数据库导出限时15分钟、预留磁盘空间至少512MiB。

每次使用独立随机快照目录。仅导出正常退出后写manifest；远端两个密文完整回读并比对SHA-256后才写complete.json。存在同名对象时只允许内容一致的幂等重试，不覆盖、不删除。上传使用Content-MD5和禁止覆盖请求头，显式请求SSE-COS。

远端回读通过不等于恢复演练通过；upload-proof明确标记尚未完成本机认证解密。本机verify-encrypted-backup脚本逐文件认证解密并校验原文哈希，丢弃解密字节，不输出明文。恢复演练仍需独立隔离数据库。

## 部署前门槛

1. 完成最小访问授权确认，确认备份目录无匿名访问；不要改附件桶原有策略。
2. 将受控公钥及根目录权限核实，创建root可读的shared/backup.env（600）。配置BACKUP_PUBLIC_KEY_FILE、BACKUP_BUCKET、BACKUP_REGION；仅在获批复用现有身份时配置BACKUP_USE_APPLICATION_IDENTITY=true。其他情况使用独立的BACKUP_COS_SECRET_ID / BACKUP_COS_SECRET_KEY，不能将凭据写入此文档或聊天。
3. 单次真实备份上传，回读密文；取回本机用原恢复私钥认证校验，再做隔离恢复演练。报告实际结果，不将单元测试替代真实COS或恢复验证。
4. 使用scripts/build-encrypted-backup.mjs构建自包含运行包，COS依赖一并打包，只保留Node内置模块为外部依赖。安装至scripts/encrypted-backup/releases/<SHA-256>/，通过current链接选择版本，不依赖业务应用的发布目录。创建backups/managed-encrypted-v1目录（root700）；安装service/timer前先使用systemd-analyze verify校验。
5. 上述通过后才启用每天北京时间03:00定时任务；Persistent仅补做一份当下备份，不补造停机期间的历史快照。失败须保留现场并告警。

本阶段无自动删除、无生命周期过期规则，不删除旧备份。需另定保存期限与费用预警，不能声称永久容量有界。

## 操作与限制

- create：生成新快照并上传；upload 加快照ID：仅重试该快照的上传与回读校验，不重新导出。
- 本机校验：node scripts/verify-encrypted-backup.mjs <私有快照目录> <本机私钥路径>。不把私钥传到云端。
- 该备份不保证抵御已获现有COS写权限的恶意主体；禁止覆盖请求头是程序保护，不是桶端不可变锁。需要更强防勒索时应采用独立身份、版本控制及专门审议的不可变保留策略。
- 仍需安排本机恢复私钥的第二份离线安全副本，避免服务器和本机任一故障导致无法恢复；不由本程序自动复制私钥。
