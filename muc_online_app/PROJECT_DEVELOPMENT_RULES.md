# 航线运行中心项目开发规则

## 1. 项目定位

- 项目名称统一为：`航线运行中心`。
- 当前核心业务模块为：`信息传达`。
- 平台作为统一门户和底座，负责登录、账号、权限、组织信息、系统配置、附件访问和公共部署能力。
- 后续一级菜单业务系统接入时，应共享同一套登录用户、权限和组织数据，不单独维护人员主数据。

## 2. 架构规则

- 当前部署形态为：前端静态页面 + Node.js 后端 API + SQLite 数据库 + 本地附件目录。
- 浏览器必须通过后端地址访问，不允许直接打开 `public/index.html`。
- 本地访问入口：

```text
http://127.0.0.1:8787/
```

- 腾讯云正式入口由 Nginx 提供 `80/443`，反向代理到：

```text
127.0.0.1:8787
```

- 公网不应直接开放 `8787`。
- 前端业务数据必须来自后端 API，不应再依赖 `localStorage / IndexedDB` 保存业务数据。
- `localStorage` 仅允许保存登录页偏好、筛选条件、分页大小等非核心业务偏好。

## 3. 目录与数据规则

- 代码目录：

```text
muc_online_app/
```

- 后端入口：

```text
server.mjs
```

- 前端资源：

```text
public/
```

- 本地数据库：

```text
data/muc.sqlite
```

- 本地附件：

```text
uploads/
```

- 腾讯云正式目录：

```text
/opt/airline-operations-center/app
/opt/airline-operations-center/data
/opt/airline-operations-center/uploads
/var/log/airline-operations-center
```

- `data/`、`uploads/`、`.env`、`backups/`、`node_modules/` 不允许提交到 GitHub。
- 本地测试数据不得上传到腾讯云，云端数据迁移前必须先备份。

## 4. 登录与角色规则

- 未登录用户只能看到登录页，不允许访问业务数据。
- 当前角色只保留：
  - 管理员
  - 发布者
  - 接收者
- 默认管理员账号 `54002010` 必须保留，不允许删除或停用。
- 系统设置入口只按管理员角色显示，不作为普通页签权限勾选项。
- 首页默认作为登录后的平台入口。

## 5. 菜单与操作权限规则

- 菜单权限决定用户能否进入一级页面。
- 操作权限决定用户能否执行具体动作。
- 信息传达的数据可见范围按固定业务规则执行，不再做单独数据范围配置：
  - 管理员：可见全部信息，包含作废审计信息。
  - 发布者：可见自己发布的信息 + 发给自己的信息。
  - 接收者：只可见发给自己的信息。
- 阅读状态只在当前用户是该信息接收对象时触发和统计。
- 修改、删除按权限勾选项控制，并且必须满足当前用户可见该信息。
- 作废 / 恢复维持既有规则：
  - 发布者可作废自己发布的信息。
  - 管理员可作废和恢复任意信息。
  - 作废信息只供管理员审计，不参与常规统计。

## 6. 信息传达业务规则

- 发布信息时，接收对象必须来自登录用户管理中的有效账号。
- 发布者不再显示普通修改入口，除非后续明确调整为按权限开放。
- 接收者和发布者作为接收对象时，未读、已读、超期、收起原文立即归类等规则必须一致。
- 管理员查看非本人接收的信息时，不触发个人阅读回执。
- 信息排序按完整日期时间倒序排列。
- 只有日期没有时间时，状态计算按当天 `12:00` 起算。
- 默认超期门限为 `3天`，默认提醒天数为 `1天`。
- 统计分析必须排除作废信息。

## 7. 附件规则

- 单个附件最大 `100MB`。
- 附件必须经过后端 `/api/attachments/:id` 权限校验，不允许直接暴露 `uploads/` 静态目录。
- 服务器实际存储文件名必须使用随机 ID，原始文件名只用于展示。
- 禁止上传或同源预览可执行网页类文件，例如 `html / js / svg / mjs`。
- 发布信息时的附件上传权限跟随发布信息权限。
- 编辑或移除信息附件权限跟随修改信息权限和资源可见规则。
- PDF 采用轻量稳定方案：
  - 电脑端弹窗内原生预览。
  - 手机端弹窗内预览内容，并提供“打开查看”使用浏览器原生缩放。
  - 不使用网页级 PDF 缩放，不引入 PDF.js。
- 图片默认适应弹窗完整显示，放大后在预览区内滚动查看。
- `.doc`、`.xls` 旧格式不做页面内解析，提示下载或另存为新格式。

## 8. 安全规则

- 所有写操作必须由后端校验登录状态和权限，前端隐藏按钮只作为界面优化。
- 未登录用户不能读取信息列表、附件、统计、系统设置等业务 API。
- 普通用户不能通过猜测附件 ID 访问无权限文件。
- 系统设置、账号管理、角色权限、分类设置等管理接口只允许管理员访问。
- Cookie 的 `Secure` 只在 `COOKIE_SECURE=true` 时启用，HTTP 测试环境不能强制 Secure。
- 正式公网部署时应使用 HTTPS 后再启用 `COOKIE_SECURE=true`。

## 9. UI 与响应式规则

- 整体风格保持现代企业级 SaaS Dashboard：
  - 浅灰背景
  - 白色圆角卡片
  - 柔和阴影
  - 清晰层级
  - 手机端不横向溢出
- 信息卡片不显示类别文字，类别通过左侧色条区分。
- 手机端统计表、反馈明细、附件弹窗、分页条只能在内部滚动，不得撑宽页面。
- 登录页不显示测试账号和快速登录按钮。
- 首页只展示简洁的平台标题和信息传达概览，不展示本地试运行提示。

## 10. 分类规则

- 默认分类为：
  - 质量发布
  - 规定要求
  - 日/周例会
  - 车间程序
  - 其他
- `其他` 是兜底分类，必须始终保留。
- 删除某分类后，历史信息自动归入 `其他`。
- 新增分类后，卡片左侧色条按分类列表顺序分配稳定颜色。

## 11. 开发与测试规则

- 修改代码后至少执行：

```bash
node --check server.mjs
node --check public/app.js
```

- 涉及部署脚本时执行：

```bash
bash -n deploy/tencent/backup-airline-operations-center.sh
```

- 提交前执行：

```bash
git diff --check
git status --short
```

- 功能修改必须回归以下核心场景：
  - 管理员登录
  - 发布者登录
  - 接收者登录
  - 信息发布
  - 带附件发布
  - 附件预览和下载
  - 收藏
  - 展开和收起原文
  - 阅读回执
  - 未读、已读、超期筛选
  - 作废和恢复
  - 统计分析与导出
  - 系统设置用户管理

## 12. Git 与发布规则

- 默认分支为 `main`。
- 上传 GitHub 前必须确认本地测试数据未被加入提交。
- 当前 GitHub 仓库：

```text
git@github.com:yuren97-zw/ceairm.git
```

- 正式部署推荐流程：
  1. 本地完成开发和测试。
  2. 提交并推送到 GitHub `main`。
  3. 云端备份现有数据库和附件。
  4. 云端同步最新代码。
  5. 重启 systemd 服务。
  6. 检查 Nginx、公网访问、登录、附件和统计。

## 13. 腾讯云部署规则

- Node 服务必须由 systemd 管理。
- Nginx 对公网提供访问，不直接暴露 Node 端口。
- 推荐环境变量：

```text
NODE_ENV=production
HOST=127.0.0.1
PORT=8787
DB_PATH=/opt/airline-operations-center/data/muc.sqlite
UPLOAD_DIR=/opt/airline-operations-center/uploads
COOKIE_SECURE=false
```

- 配置 HTTPS 后将 `COOKIE_SECURE` 改为 `true`。
- Nginx 上传限制建议：

```text
client_max_body_size 120m
proxy_read_timeout 300s
proxy_send_timeout 300s
client_body_timeout 300s
```

- 每日备份数据库和附件，至少保留 7 到 30 天。
- 腾讯云防火墙只保留必要端口：
  - `22`
  - `80`
  - `443`
- 不保留公网 `8787`。
